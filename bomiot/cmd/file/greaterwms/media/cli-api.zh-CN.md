# bomiot api

在当前工作空间中创建一个新的 **API 应用**，生成一套开箱可用的完整接口骨架（增删改查）。

```bash
bomiot api <name>
```

## 概述

`bomiot api <name>` 与 `bomiot app` 类似，都会创建应用文件夹并完成注册，区别在于骨架内容：**api 生成的是一套完整的 CRUD 接口模板**——模型、序列化器、筛选器、视图、路由一步到位，创建后即拥有一组可调用的 RESTful 接口，适合快速搭建数据接口；app 生成的是基础骨架，需要自己逐步填充。

命令必须在**工作空间根目录**下执行，且工作空间处于项目模式。

## 参数

| 参数 | 说明 |
|---|---|
| `<name>` | 应用名称（必填）。作为应用文件夹名与接口路径前缀，需为合法的目录名 |

## 命名约束

| 情况 | 结果 |
|---|---|
| 未提供名称 | 提示 `Please enter your app name` |
| 名称为 `bomiot`（保留名） | 提示 `Invalid app name`，拒绝创建 |
| 同名应用目录已存在 | 提示 `App directory already exists`，拒绝创建 |

## 生成的内容

| 文件 | 说明 |
|---|---|
| `models.py` | 示例数据模型 |
| `serializers.py` | 序列化器 |
| `filter.py` | 查询筛选器 |
| `views.py` | 接口视图（增删改查） |
| `urls.py` | 路由注册（接口路径以应用名为前缀） |

骨架中的所有示例标识会自动替换为你的应用名，创建后即可直接调用。

## 与 app 的区别

| 对比 | `bomiot app` | `bomiot api` |
|---|---|---|
| 骨架内容 | 基础目录结构 | 完整 CRUD 接口模板 |
| 适用场景 | 从零搭建自定义功能 | 快速产出可调用的数据接口 |
| 创建后 | 需自行编写模型与接口 | 自带示例接口，改模型即可用 |

## 典型流程

```bash
bomiot api goods         # 创建商品接口应用
# 按需修改 models.py 中的示例模型
bomiot makemigrations    # 生成迁移
bomiot migrate           # 应用迁移
bomiot run               # 启动，即可调用 goods 相关接口
```

## 注意事项

- 骨架中的示例模型仅供起步参考，请按业务需要修改后**务必执行迁移**，否则接口操作的是不存在的表
- 命名建议与 app 一致：小写字母、数字、下划线
- 创建失败（重名/保留名/模式不对）不会写入任何文件，可放心重试
- 删除应用需手动移除文件夹并清理注册与迁移记录，没有对应的删除命令
