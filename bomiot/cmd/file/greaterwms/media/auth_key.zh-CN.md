# auth_key.py

## 概述

`auth_key.py` 是 Bomiot 在应用启动时自动生成的**设备绑定密钥文件**，存放在可执行程序所在目录。文件中包含两个基于本机唯一标识生成的密钥：`COMMUNITY_KEY` 和 `SPONSOR_KEY`。

该文件用于区分两种使用场景：开发 / 传统服务器部署时不校验，可免费使用；通过 `bomiot deploy` 进行跨平台节点化分发时，会校验密钥，每台设备仅有 7 天有效期，过期后需使用 `SPONSOR_KEY` 到 Bomiot 官网赞助订阅续费。

---

## 文件内容

```python
COMMUNITY_KEY = "MDA6RTA6NEU6MTA6..."
SPONSOR_KEY = "MDA6RTA6NEU6MTA6..."
```

| 字段 | 说明 |
| --- | --- |
| `COMMUNITY_KEY` | 社区版密钥，用于社区版授权校验 |
| `SPONSOR_KEY` | 赞助版密钥，用于官网赞助订阅续费 |

---

## 生成时机

`auth_key.py` 由 `launcher.py` 在应用启动时自动生成，无需手动创建。

**生成流程：**

1. 定位到可执行程序所在目录（`os.path.dirname(sys.executable)`）
2. 若已存在 `auth_key.py`，先删除旧文件
3. 调用 `bomiot_token.encrypt_info()` 生成 `community_key` 和 `sponsor_key`
4. 若生成的密钥中包含 `/`，则重新生成（避免写入文件时出现路径问题）
5. 将两个密钥写入 `auth_key.py`

## 两种使用场景

### 场景一：开发 / 传统服务器部署（免费）

通过 `bomiot run` 启动服务，或以传统 Django / FastAPI 方式部署到服务器时：

- Bomiot **不会校验** `auth_key.py` 中的密钥
- 所有功能可**免费使用**，无任何限制
- `auth_key.py` 仅作为文件存在，不影响运行

```bash
bomiot run --host 0.0.0.0 --port 8000
```

### 场景二：跨平台节点化分发（赞助专享）

通过 `bomiot deploy` 生成跨平台绿色版运行文件，分发到物理设备 / 本地节点运行时：

- Bomiot **会校验** `auth_key.py` 中的密钥
- 每台设备仅有 **7 天有效期**
- 超过 7 天后，程序不可继续使用
- 需携带 `auth_key.py` 中的 `SPONSOR_KEY` 到 [Bomiot 官网](https://www.bomiot.com) 完成赞助订阅续费

```bash
bomiot deploy
```

> ⚠️ **节点化分发面向物理设备 / 本地节点，不支持部署到云服务器。** 目标运行环境为企业内网的实际物理设备（PC、工控机、边缘网关、树莓派、本地机房服务器等）。如需部署到云服务器，请使用「传统服务器部署」方式。

## 7 天有效期与续费

| 项目 | 说明 |
| --- | --- |
| 有效期 | 7 天（自首次运行起算） |
| 过期后果 | 程序不可继续使用 |
| 续费方式 | 携带 `SPONSOR_KEY` 到 Bomiot 官网赞助订阅 |
| 绑定关系 | 密钥绑定本机唯一标识，换机需重新生成 |

---

## 注意事项

1. **自动生成**：`auth_key.py` 由 `launcher.py` 在启动时自动生成，无需手动创建或维护
2. **设备绑定**：密钥基于本机唯一标识生成，仅对当前设备有效，换机需重新生成
3. **本地校验**：所有校验均在本地完成，不会上传节点信息或业务数据
4. **传统部署免费**：开发和传统服务器部署场景下不校验密钥，可免费使用全部功能
5. **节点分发需赞助**：`bomiot deploy` 跨平台分发场景下启用校验，每台设备 7 天有效期，过期需续费
6. **请勿手动修改**：`auth_key.py` 由程序自动生成，手动修改可能导致校验失败
