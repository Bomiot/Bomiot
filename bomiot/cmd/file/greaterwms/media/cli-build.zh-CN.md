# build

`bomiot build` 是 Bomiot 的一键构建命令，用于将当前项目编译为**独立可分发的应用程序**。构建产物在目标机器上运行时无需安装 Python 环境，同时自动生成增量更新所需的清单文件。

## 使用前提

在**项目根目录**下执行，并确保以下文件存在：

| 文件 | 必需 | 说明 |
|---|---|---|
| `launcher.py` | 是 | 项目启动入口，必须包含 `app_name`、`version`、`base_url` 三个变量定义 |
| `setup.ini` | 是 | 项目配置文件，其中 `[debug]` 段的 `debug` 值会影响 macOS 构建产物（见下文「平台差异」） |
| `builder.toml` | 否 | 额外的构建配置，用于在默认打包范围之外追加需要包含的包、模块或数据文件 |

## 基本用法

```bash
bomiot build
```

无需任何参数。命令会自动识别当前操作系统与 CPU 架构，完成整个构建流程。

## 执行流程

命令执行时按以下阶段依次进行，每个阶段都会在终端输出 `[builder]` 前缀的日志：

1. **密钥准备** — 准备本次构建的授权密钥，并写入构建产物
2. **读取项目信息** — 从 `launcher.py` 读取应用名称、版本号与更新地址
3. **规范运行参数** — 自动将并发工作进程数固定为 1，保证打包产物行为一致
4. **生成应用清单** — 扫描项目并生成 `apps.json`
5. **识别目标平台** — 确定操作系统（Windows / macOS / Linux）与架构（x64 / arm64）
6. **执行编译** — 调用编译器进行独立打包，编译过程实时输出日志
7. **整理产物** — 结束后台残留进程、按规范重命名输出目录、写入授权文件
8. **生成更新清单** — 对全部产物文件生成哈希清单，供增量更新使用

全部完成后，终端会输出产物目录与总耗时。

## 构建输出

构建产物位于项目根目录的 `build/` 下：

| 输出 | 说明 |
|---|---|
| `build/{app_name}-{version}-{OS}/` | 完整可分发目录，整个目录拷贝到目标机器即可运行 |
| `build/manifest-{os}-{arch}.json` | 增量更新清单文件，更新服务据此判断需要下载哪些文件 |

## CI 环境

在 GitHub Actions 等 CI 环境中运行时，命令会自动切换为 CI 模式，通过环境变量注入构建所需信息：

| 环境变量 | 必需 | 说明 |
|---|---|---|
| `COMMUNITY_KEY` | 是 | 授权密钥，由 CI 流水线注入 |
| `SPONSOR_KEY` | 是 | 授权密钥，由 CI 流水线注入 |
| `APP_NAME` / `BASE_VERSION` | 否 | 同时设置时覆盖 `launcher.py` 中的应用名与版本号 |
| `BASE_URL` | 否 | 配合上两项使用时注入更新地址 |

CI 环境下缺少必需的密钥变量时，构建会**直接失败中止**，以便流水线及时暴露问题。

## 平台差异

| 行为 | Windows | macOS |
|---|---|---|
| 控制台窗口 | 构建产物始终保留控制台能力，运行时根据 `setup.ini` 的 `debug` 值显示或隐藏，**改配置即生效** | 由构建时 `setup.ini` 的 `debug` 值决定：`True` 则启动时显示控制台，`False` 则无控制台。**改动后需重新构建** |
| 并行编译 | 自动按本机 CPU 核数分配 | 同左；CI 环境中固定提高并行度以加速构建 |

## builder.toml（可选）

构建默认包含项目运行所需的全部内容。当项目引入了额外的第三方包、数据文件，或需要排除某些文件时，在项目根目录创建 `builder.toml`，在 `[build]` 段中按需配置。所有配置项都在默认范围之上**追加合并**（与默认内容重复的项自动忽略），无需重复声明。

### 配置项一览

```toml
[build]
# 额外打包的 Python 包（整个包）
include_packages = ["my_package"]

# 额外打包包内的数据文件（模板、静态资源、语言文件等）
include_package_data = ["my_package"]

# 额外打包的单个 Python 模块
include_modules = ["my_module"]

# 构建分析时不跟随其导入的包，用于裁剪体积、避免误打包
nofollow_import_to = ["some_package.tests"]

# 额外复制的单个文件，格式为 "源路径=目标路径"
# 源路径相对项目根目录，目标路径相对输出目录
include_data_files = ["logo.png=logo.png"]

# 额外复制的整个目录，格式同为 "源路径=目标路径"
include_data_dirs = ["assets=assets"]

# 从产物中排除的文件，支持通配符
noinclude_data_files = ["*.map", "docs/**/*"]
```

### 注意事项

- 所有配置项均为数组，省略或留空即只使用默认范围
- `include_data_files` 与 `include_data_dirs` 必须使用 `源=目标` 的等号格式
- 排除规则的通配符中，`*` 不匹配目录分隔符，多层目录需逐级书写（如 `docs/*` 与 `docs/**/*`）
- 配置错误（如路径不存在）不会中断构建，但对应内容不会出现在产物中，建议构建后检查输出目录
