# Project Configuration (setup.ini)

`setup.ini` lives at the workspace root (next to the project directory) and is generated by `bomiot init`. The framework reads it once at startup: database, throttling, JWT, file upload, mail, and background services are all configured here. The desktop launcher also reads parts of it (such as the console window switch). Restart the service after any change.

## Full Configuration

```ini
[project]
name = greaterwms

[debug]
debug = True

[database]
# engine, Accept (sqlite, mysql, oracle, postgresql)
engine = sqlite
name = db_name
user = db_user
password = db_pwd
host = db_host
port = db_port

[templates]
name = templates/dist/spa/index.html

[locale]
time_zone = 'UTC'

[throttle]
allocation_seconds = 1
throttle_seconds = 10

[request]
limit = 2

[jwt]
user_jwt_time = 1000000

[file]
file_size = 102400000
file_extension = py,png,jpg,jpeg,gif,bmp,webp,txt,md,html,htm,js,css,json,xml,csv,xlsx,xls,ppt,pptx,doc,docx,pdf

[mail]
email_host = email_host
email_port = 465
email_host_user = email_host_user
email_host_password = email_host_password
default_from_email = default_from_email
email_from = email_from
email_use_ssl = True

[system_control]
observer = False
scheduler = True
server_monitor = False
```

## [project]

| Key | Fallback | Description |
|-----|----------|-------------|
| `name` | `greaterwms` | Project name, fixed as `greaterwms` — do not change. The framework uses it as the root path for templates, static files, media, and dynamic app scanning; changing it will prevent the project from starting |

## [debug]

| Key | Fallback | Description |
|-----|----------|-------------|
| `debug` | `True` | Master switch for debug mode |

This value drives two behaviors:

- **Framework debug mode**: read at startup as the service DEBUG flag.
- **Console in build packages**: when `debug = True`, packages produced by `bomiot build` ship with a console window. On Windows the launcher shows / hides that console on every launch according to this value (takes effect immediately); on macOS the value is baked into the app bundle at build time, so rerun `bomiot build` after changing it (see the CLI build doc).

## [database]

| Key | Fallback | Description |
|-----|----------|-------------|
| `engine` | `sqlite` | Database engine: `sqlite` / `mysql` / `postgresql` / `oracle` |
| `name` | — | Database name |
| `user` | — | Username |
| `password` | — | Password |
| `host` | — | Host |
| `port` | — | Port |

- `sqlite`: zero configuration — `db.sqlite3` is created automatically under the workspace `dbs/` directory; the remaining keys are not needed.
- Other engines: `name` / `user` / `password` / `host` / `port` are all required, and the database must be created beforehand.

## [templates]

| Key | Fallback | Description |
|-----|----------|-------------|
| `name` | `templates/dist/spa/index.html` | Relative path of the frontend SPA entry HTML. Point the frontend build output here and the service will host it; normally no change needed |

## [locale]

| Key | Fallback | Description |
|-----|----------|-------------|
| `time_zone` | `'UTC'` | Service timezone, also used by the task scheduler |

> Note: the current framework version reads this value from a section named `local`, while the shipped `setup.ini` uses `[locale]`, so the effective value stays at the fallback `'UTC'`. To customize the timezone, write the section as `[local]`.

## [throttle]

| Key | Fallback | Description |
|-----|----------|-------------|
| `allocation_seconds` | `1` | Minimum interval (seconds) between two requests from the same IP |
| `throttle_seconds` | `10` | Maximum number of requests allowed within the interval window |

Together they form request throttling: when requests arrive more frequently than `allocation_seconds` and the count within the window reaches `throttle_seconds`, further requests are rejected.

## [request]

| Key | Fallback | Description |
|-----|----------|-------------|
| `limit` | `2` | Maximum consecutive failed login attempts. The account is deactivated automatically once exceeded, and an admin must re-enable it |

## [jwt]

| Key | Fallback | Description |
|-----|----------|-------------|
| `user_jwt_time` | `1000000` | Login token lifetime in seconds. The frontend must log in again after expiry |

## [file]

| Key | Fallback | Description |
|-----|----------|-------------|
| `file_size` | `102400000` | Maximum size of a single uploaded file in bytes (about 100 MB) |
| `file_extension` | See config | Whitelist of allowed upload extensions, comma-separated, without dots |

Uploads exceeding the size limit or outside the extension whitelist are rejected.

## [mail]

| Key | Fallback | Description |
|-----|----------|-------------|
| `email_host` | — | SMTP host |
| `email_port` | `465` | SMTP port |
| `email_host_user` | — | SMTP account |
| `email_host_password` | — | SMTP password / authorization code |
| `default_from_email` | — | Default sender address |
| `email_from` | — | Sender display name |
| `email_use_ssl` | `True` | Whether to use SSL |

## [system_control]

| Key | Fallback | Description |
|-----|----------|-------------|
| `observer` | `True` | File-watcher process; watches the project directory for changes |
| `scheduler` | `True` | Task scheduler process; when off, all scheduled jobs stop running |
| `server_monitor` | `True` | Server resource monitor process (CPU / memory / disk, etc.) |

- All three switches are read at service startup; a missing section or key is treated as `True`.
- In the shipped configuration, `observer = False` and `server_monitor = False` (turned off to save resources), while `scheduler = True` keeps scheduled jobs running.
- With multiple workers, a file lock ensures these background processes start only once, regardless of worker count.

## When Changes Take Effect

- `setup.ini` is read once at process startup — **restart the service** (or the desktop app) after any modification.
- For macOS apps, `debug` is a build-time setting: rerun `bomiot build` after changing it.
