# auth_key.py

## Overview

`auth_key.py` is a **device-bound key file** automatically generated by Bomiot at application startup, stored in the directory where the executable resides. The file contains two keys generated based on the local machine's unique identifier: `COMMUNITY_KEY` and `SPONSOR_KEY`.

This file distinguishes two usage scenarios: for development / traditional server deployment, the keys are not verified and the software is free to use; for cross-platform node-based distribution via `bomiot deploy`, the keys are verified and each device has only a 7-day validity period. After expiration, you need to use `SPONSOR_KEY` on the Bomiot official website to renew the sponsorship subscription.

---

## File Content

```python
COMMUNITY_KEY = "MDA6RTA6NEU6MTA6..."
SPONSOR_KEY = "MDA6RTA6NEU6MTA6..."
```

| Field | Description |
| --- | --- |
| `COMMUNITY_KEY` | Community edition key, used for community edition authorization verification |
| `SPONSOR_KEY` | Sponsor edition key, used for sponsorship subscription renewal on the official website |

---

## Generation Timing

`auth_key.py` is automatically generated by `launcher.py` at application startup; no manual creation is required.

**Generation process:**

1. Locate the directory where the executable resides (`os.path.dirname(sys.executable)`)
2. If `auth_key.py` already exists, delete the old file first
3. Call `bomiot_token.encrypt_info()` to generate `community_key` and `sponsor_key`
4. If the generated keys contain `/`, regenerate them (to avoid path issues when writing to the file)
5. Write both keys to `auth_key.py`

## Two Usage Scenarios

### Scenario 1: Development / Traditional Server Deployment (Free)

When starting the service via `bomiot run`, or deploying to a server in the traditional Django / FastAPI way:

- Bomiot **does not verify** the keys in `auth_key.py`
- All features are **free to use** without any restrictions
- `auth_key.py` merely exists as a file and does not affect runtime

```bash
bomiot run --host 0.0.0.0 --port 8000
```

### Scenario 2: Cross-Platform Node-Based Distribution (Sponsor Only)

When generating cross-platform portable runtime files via `bomiot deploy` and distributing them to physical devices / local nodes:

- Bomiot **verifies** the keys in `auth_key.py`
- Each device has only a **7-day validity period**
- After 7 days, the program can no longer be used
- You need to bring the `SPONSOR_KEY` from `auth_key.py` to the [Bomiot official website](https://www.bomiot.com) to complete the sponsorship subscription renewal

```bash
bomiot deploy
```

> ⚠️ **Node-based distribution targets physical devices / local nodes only; cloud server deployment is NOT supported.** The target runtime environment is actual physical devices within the enterprise intranet (PCs, industrial PCs, edge gateways, Raspberry Pi, on-premise data-center servers, etc.). If you need to deploy to a cloud server, please use the "Traditional Server Deployment" method.

---

## 7-Day Validity and Renewal

| Item | Description |
| --- | --- |
| Validity period | 7 days (counted from the first run) |
| Consequence of expiration | The program can no longer be used |
| Renewal method | Bring `SPONSOR_KEY` to the Bomiot official website for sponsorship subscription |
| Binding relationship | Keys are bound to the local machine's unique identifier; a new device requires regeneration |

---

## Notes

1. **Auto-generated**: `auth_key.py` is automatically generated by `launcher.py` at startup; no manual creation or maintenance is required
2. **Device-bound**: Keys are generated based on the local machine's unique identifier and are only valid for the current device; a new device requires regeneration
3. **Local verification**: All verifications are completed locally; no node information or business data is uploaded
4. **Free for traditional deployment**: In development and traditional server deployment scenarios, keys are not verified and all features are free to use
5. **Sponsorship required for node distribution**: In the `bomiot deploy` cross-platform distribution scenario, verification is enabled; each device has a 7-day validity period and requires renewal after expiration
6. **Do not modify manually**: `auth_key.py` is automatically generated by the program; manual modification may cause verification to fail
