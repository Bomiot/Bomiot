# bomiot publish

将一个已构建的平台产物发布到更新服务器，供客户端增量更新。

```bash
bomiot publish --os=windows --code=example
```

## 命令参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `--os` | 是 | 目标平台标识，取值：`windows`、`macos`、`linux`（小写） |
| `--code` | 是 | 发布口令。由服务器校验，防止他人拿到 build.json（项目的唯一标识）后冒充该项目，向服务器上传被篡改的更新文件。忘记后可在 update 应用的 UpdateModel 数据表 `verify_code` 字段中查看 |

命令必须在**项目根目录**（`launcher.py` 所在目录）下执行。

## 使用前提

1. 已通过 `bomiot build` 完成对应平台的构建，产物位于 `build/` 目录下（清单文件与输出目录齐全）
2. `launcher.py` 中定义了 `app_name` 与 `base_url`（更新服务器地址）
3. 持有正确的发布口令（`--code`）

> 可以发布与当前机器不同的平台产物（例如在 Windows 上发布 macOS 包），只要 `build/` 目录中存在该平台的构建产物。

## 执行流程

```text
bomiot publish --os=windows --code=example
  │
  ├─ 1. 读取 launcher.py，获取 app_name 与 base_url
  ├─ 2. 携带 --code 向服务器请求校验发布口令
  ├─ 3. 在 build/ 目录定位该平台的清单文件与输出目录
  ├─ 4. 向服务器确认该版本是否需要发布
  ├─ 5. 需要发布时，将清单与产物打包并上传
  └─ 6. 发布完成，客户端下次启动即可获取该版本
```

发布结果说明：

- **需要发布**：打包上传，完成后提示发布成功
- **无需发布**：服务器上已存在相同版本与平台的产物，命令直接结束，不会重复上传
- **找不到产物**：`build/` 目录下没有对应平台的构建产物时，命令报错退出，不会产生任何上传

## 与 launcher.py 的增量更新协作

发布端（bomiot publish）与客户端（launcher.py）通过一套**命名约定**对齐，服务器只负责按名字存取，不参与平台判断。

### 命名约定

| 产物 | 命名格式 | 示例 |
|---|---|---|
| 清单文件 | `manifest--{app_name}-{os}-{arch}.json` | `manifest--MyApp-windows-x64.json` |
| 构建输出目录 | `{app_name}-{version}-{os}` | `MyApp-1.0.0-windows` |
| 上传压缩包 | `{app_name}--{version}-{os}.tar.xz` | `MyApp--1.0.0-windows.tar.xz` |

`os` 与 `arch` 在构建时写入清单文件名。发布端按 `--os` 参数定位清单；客户端启动时探测自身平台，按同样的规则拼出自己的清单名向服务器请求——Windows x64 的客户端只会获取 windows-x64 的更新，多平台互不干扰。

### 更新流程

1. **客户端启动**：launcher.py 读取本地清单，向 `POST /update/` 请求远端该平台的版本摘要
2. **比对**：摘要与本地一致则直接启动；不一致则进入更新
3. **拉取清单**：从 `POST /update/manifest/` 获取远端完整清单（记录每个文件的校验信息）
4. **求差下载**：对比本地与远端清单，仅下载新增和有变化的文件；大文件支持按块下载与断点续传，下载地址为 `/update/download/...`
5. **应用更新**：下载完成后生成更新脚本，应用退出，由脚本完成文件替换并重启
6. **容错**：下载中断或校验失败时放弃本次更新，应用按本地版本正常启动，下次启动重试

用户的业务数据目录（数据库、日志、缓存等）在更新过程中不受影响。

## 服务端接口

更新服务由 `greaterwms.update` 应用提供，挂载在 `base_url` 的 `/update/` 路径下：

| 端点 | 方法 | 用途 |
|---|---|---|
| `/update/` | POST | 客户端版本摘要比对 |
| `/update/manifest/` | POST | 获取指定平台的完整清单 |
| `/update/download/<path>` | GET | 下载更新文件（支持 Range 分块） |
| `/update/publish/` | POST | 发布前确认版本状态 |
| `/update/upload/` | POST | 上传发布产物 |

## 注意事项

- `--os` 参数为小写，且必须与构建产物的平台标识一致；写错会提示找不到清单文件，不会产生错误发布
- 发布口令错误会被服务器拒绝，不会上传任何内容
- 重复发布同一版本同一平台时，服务器会提示无需发布，命令直接结束
- 为防止他人向更新服务器 POST 文件，建议修改自动更新的 URL 地址并更改更新文件的存放地址；若修改了文件存放地址，`launcher.py` 中的存放地址也需要同步修改，否则客户端无法下载更新文件
